# AGENTS.md — instructions for any coding agent (Claude Code, Codex, Copilot, Cursor)

Same rules for every agent. `CLAUDE.md` and `.github/copilot-instructions.md` point here.

## What this repo is

A thin, testable slice of an agentic RAG system that reads a knee DBQ (VA Form 21-0960M-9
structure), extracts typed findings with span-level provenance, retrieves rating criteria and
exam-adequacy rules from a small qualifiers KB (38 CFR Part 4 + case law), evaluates, flags gaps,
verifies every claim (evidence span + citation), and emits a report for a human reviewer.

Decision support for a VSO or attorney. Never an automated rating. Never claim otherwise in
code, docs, or prompts.

## Non-negotiables

1. PHI never crosses the boundary. Only fields listed in `dbq_agent.phi.FREE_TEXT_FIELDS` may reach
   an LLM, and only after `Deidentifier.deidentify()`. Identity fields (`IDENTITY_FIELDS`) never
   leave the process. `tests/test_phi.py` enforces this with a capturing fake client; keep it green.
2. Numbers are rules, not LLM output. ROM thresholds, tier selection, 4.31 / 4.59 / 4.7 handling
   live in `steps/evaluate.py` as deterministic code. An LLM may only read free text.
3. Every claim carries evidence spans and citations. `steps/verify.py` drops anything that does
   not resolve to a real field/page and a real KB authority id. Do not weaken it.
4. The KB is data, not prose in a prompt. Add criteria to `data/kb/criteria.json` and rules to
   `data/kb/adequacy.json`; cite real authority ids from `data/kb/authorities.json`. If you are not
   sure a citation is right, set `"verify": true` on it rather than guessing.
5. Synthetic data only. Never commit a real DBQ or real veteran data. `cases/` is generated by
   `dbq_agent.synth.knee`.

## Toolchain

- `uv sync --all-extras` — install (Python pinned in `.python-version`).
- `uv run ruff check . && uv run ruff format --check .`
- `uv run pyright`
- `uv run pytest`
- `uv run dbq-agent run cases/knee_01.pdf` / `uv run dbq-agent eval`

All four checks must pass before you say a task is done.

## Layout

```
src/dbq_agent/
  models.py      Pydantic types shared by every step (Span, Claim, State, ...)
  kb.py          KB loader + retrieve(dc, claim_date, tags)
  ingest.py      pypdf AcroForm read with field/page provenance
  phi.py         Deidentifier (known values + patterns + optional phi-scrub), re-identify
  extract.py     structured findings (rules) + free-text extractor (heuristic or LLM)
  llm.py         LLMClient protocol, AnthropicClient, CapturingClient (tests)
  steps/         classify, retrieve, evaluate, gap_check, verify — pure functions on State
  pipeline.py    runner with bounded re-retrieval
  report.py      JSON + markdown report
  evaluate_cases.py  metrics vs cases/truth.json
  cli.py         dbq-agent run | eval | synth
  synth/knee.py  KneeTruth -> fillable PDF
data/kb/         criteria.json, adequacy.json, authorities.json
cases/           synthetic PDFs + truth.json
NOTES.md         restart note — update it when you stop mid-task
```

## Style

- Python 3.12+ typing, Pydantic v2, no bare `dict` state between steps.
- Small pure functions; a step takes `State` and a `Context` and returns a new `State`.
- Prefer adding a test over adding a comment.
- Keep `NOTES.md` current: goal, state, next step, verify, blockers.
