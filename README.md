# dbq-qualifier-agent

Agentic RAG slice that reads a knee DBQ (VA Form 21-0960M-9 structure), maps the findings to
38 CFR Part 4 rating criteria with span-level provenance, checks exam adequacy against the case
law raters actually apply (Correia, DeLuca, Sharp, Mitchell, Nieves-Rodriguez), and refuses to
emit any claim it cannot ground in a page + field and a real citation.

Decision support for a VSO or attorney. Not an automated rating.

```
DBQ PDF ─► ingest ─► PHI gate ─► extract ─► classify ─► retrieve ─► evaluate ─► gap check ─► verify ─► report
           (pypdf)   (redact)    (rules +   (DC route)  (38 CFR +   (rules)     (Correia,     (critic;    (JSON + md,
                                  free text)             case law)              DeLuca...)     re-retrieve) re-identified)
```

## Why this shape

- Numbers come from rules, not from a model. Tier selection, § 4.31, § 4.59 painful-motion
  minimum, most-limiting ROM under DeLuca — all deterministic code in `steps/evaluate.py`.
- A model (Claude) only ever reads free text, only after de-identification, and only to pull
  out things a regex cannot: a flare-up estimate buried in the remarks, whether an opinion has
  a reasoned rationale. Its quotes must be verbatim or they are discarded.
- The qualifiers are a corpus, not prompt text: `data/kb/criteria.json` holds criteria as rows
  with effective dates (the version in force on the claim date controls), `adequacy.json` holds
  the exam-adequacy rules, `authorities.json` holds what can be cited.
- The critic is the agentic part. `steps/verify.py` rejects any claim without a resolvable
  evidence span and a retrieved citation; when a citation exists in the KB but was not retrieved
  it sends the pipeline back to retrieval, at most `max_retrieval_iterations` times.
- An inadequate exam yields `rating: null`, a provisional mapping, and the gaps with the cases
  that make them gaps — which is what a reviewer needs to request a clarification or a remand.

## Scope of this slice

| In | Out (next) |
| --- | --- |
| Knee DBQ structure, one joint | Other DBQs (PTSD general rating formula = LLM-judged tiers) |
| DC 5260 / 5261 | DC 5257 (instability, revised 2021), 5003, 5258/5259, 5256 |
| Fillable AcroForm PDFs | Scanned DBQs (OCR + layout, e.g. Docling) |
| Structured + lexical retrieval over a small KB | Hybrid BM25 + dense (Qdrant) once the KB grows |
| Heuristic or Claude free-text extractor | Combined ratings (§ 4.25), bilateral factor |
| Synthetic cases only | Real form field-name mapping |

## Quick start

```bash
uv sync --all-extras
uv run dbq-agent eval --claim-date 2026-09-01        # scores the 10 synthetic cases
uv run dbq-agent run cases/knee_07.pdf --claim-date 2026-09-01   # an inadequate exam (Correia)
uv run dbq-agent run cases/knee_05.pdf --claim-date 2026-09-01 --json out.json
ANTHROPIC_API_KEY=... uv run dbq-agent run cases/knee_05.pdf --llm anthropic
```

`uv run ruff check . && uv run pyright && uv run pytest` must all pass before a change is done.

## PHI boundary

Two enforced mechanisms (`src/dbq_agent/phi.py`, `tests/test_phi.py`):

1. Allowlist. Identity fields (`vet_name`, `vet_dob`, `vet_ssn`, `exam_date`, `examiner_name`) are
   read into an `Identity` object that no step serializes. Only `FREE_TEXT_FIELDS` can reach a
   model, and only through `Deidentifier.deidentify()`.
2. Redaction of the free text itself. Three detectors are merged: the identity values we already
   parsed (name variants, DOB in several formats), pattern detectors (SSN, phone, e-mail, dates),
   and [`phi-scrub`](https://pypi.org/project/phi-scrub/) when installed (`uv sync --extra phi`).
   Numbered tokens (`[NAME_1]`, `[DOB_1]`) map back to originals inside the boundary only; the
   report re-identifies quotes for the human reviewer.

`test_llm_payloads_never_contain_phi` runs the whole pipeline against a capturing fake model
and asserts no identity value appears in any payload.

## Synthetic cases

`cases/` holds ten fictional knee exams generated by `dbq_agent.synth` (regenerate with
`uv run dbq-agent synth`). Seven are adequate; three are deliberately inadequate:

| Case | What it exercises | Expected |
| --- | --- | --- |
| knee_01 | flare estimate in the same tier | 5260 10%, 5261 0% |
| knee_02 | flexion 30 / extension 10; opposite joint unmeasured | 20% + 10%, advisory gap |
| knee_03 | noncompensable ROM, painful motion | 5260 10% via § 4.59 (Burton) |
| knee_04 | repetitive use is the limiting measurement | 5260 10% (DeLuca), § 4.7 flag on 5261 |
| knee_05 | flare estimate only in the remarks | 5260 20% from free text, quote verified |
| knee_06 | extension-limited knee, arthritis, pain/function unaddressed | 5261 30%, DC 5003 note, Mitchell gap |
| knee_07 | passive ROM pain not tested, no reason | **inadequate** (Correia), provisional 10% |
| knee_08 | flare-ups, unexplained "speculation" | **inadequate** (Sharp / Jones), provisional 5261 10% |
| knee_09 | no repetitive-use testing, bare opinion | **inadequate** (DeLuca), opinion gap |
| knee_10 | 33° flexion with weakness + fatigability | 10% with § 4.7 consider flag |

`dbq-agent eval` reports tier precision/recall, adequacy accuracy, gap precision/recall, the
§ 4.7 consider-flag precision/recall, and citation faithfulness over every emitted claim.

## Policy choices you may want to change

All in `steps/evaluate.py`, each with a docstring:

- § 4.59 minimum is applied once, under DC 5260, only when neither ROM code is compensable.
- § 4.7 is never applied automatically; a `consider_higher` claim is raised when the effective
  ROM is within 5° of the next tier and the exam documents weakness, fatigability or
  incoordination.
- Blocking vs advisory severity of each adequacy rule is data in `data/kb/adequacy.json`.
